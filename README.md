# NEX-GATE: ID-card geofence login / logout

ESP32-C3 ID cards report a phone-supplied GPS position. The server decides inside or outside the college geofence, logs **Login** (entered) and **Logout** (left), and shows everything on a live Leaflet map.

```
phone GPS --hotspot WiFi--> ESP32-C3 card --HTTPS--> Render server --live stream--> admin map
```

* No database and no cloud storage. The gate log lives in memory and keeps **only the last 20 entries**; each new one pushes the oldest out.
* `/admin` live map: moving cards with trails, geofence (circle or polygon, editable), activity feed, sound alerts.
* `/register` register cards: cards that power on appear automatically, click one, add the student, done.
* Both pages are behind one admin password.

## 1. Try it locally (no hardware)

```bash
npm install
ADMIN_PASSWORD=pick-one DEVICE_KEY=secret123 npm start     # http://localhost:3000
DEVICE_KEY=secret123 npm run simulate                       # second terminal: 5 fake cards
```
Open `/register`, register `SIM-001` to `SIM-005`, then watch `/admin`. (Windows PowerShell: set `$env:ADMIN_PASSWORD="..."` first.)

## 2. Deploy on Render

1. Push this folder to a GitHub repo (for example under Nexus-labs2).
2. Render, **New, Blueprint**, pick the repo (it reads `render.yaml`). Or **New, Web Service** with build `npm install` and start `npm start`.
3. Set environment variables:
   * `ADMIN_PASSWORD`: your admin login.
   * `DEVICE_KEY`: auto-generated by the blueprint. Copy it, the firmware needs it.
   * `SESSION_SECRET`: auto-generated.
   * `STORE_SEED` (optional, see below).
4. Open `https://<your-service>.onrender.com`, sign in, then drag the geofence over your college (**Edit boundary**, then **Save boundary**).

**Free plan notes**
* Free services sleep after ~15 min with no traffic, and the file system is wiped when they restart. Cards ping every 5 s, so it stays awake while cards are on; the first ping after a sleep can take about 50 s (the firmware just retries).
* The 20-entry log is intentionally memory-only. The **registry and geofence** are saved to a file, which free Render may lose on restart. To keep them: on `/register` click **Copy backup**, then paste it into the `STORE_SEED` env var on Render. They reload on every boot. (A paid instance with a disk also works.)

## 3. Flash a card

1. Arduino IDE, install the **esp32** board package. Board: *ESP32C3 Dev Module*, *USB CDC On Boot: Enabled*.
2. Edit `firmware/nex_card/config.h`: phone hotspot name and password (2.4 GHz), your Render hostname, `DEVICE_KEY`.
3. Upload `firmware/nex_card/nex_card.ino`. The serial monitor prints the **Card ID** (like `NEX-1A2B3C`) and the card's address.
4. Power it on near the phone hotspot. The card appears under **Cards waiting to be registered** on `/register`.

On-board LED: solid = inside the geofence, short blink = report sent.

## 4. Phone setup (how the card gets GPS)

The card has no GPS, so the phone feeds it. It serves a small page at `http://nexcard-XXXXXX.local/` (or its IP from the serial monitor).

* **Option A, browser page.** Browsers only allow location on secure pages, and the card's page is plain http. In Chrome on the phone open `chrome://flags/#unsafely-treat-insecure-origin-as-secure`, add `http://nexcard-XXXXXX.local` (or the IP), enable, relaunch, then open the page and allow location. Keep the page open.
* **Option B, no browser limits.** Any app that can send an HTTP request with the phone location works, for example HTTP Shortcuts or Tasker: `GET http://<card>/gps?lat=%lat&lng=%lng&acc=%acc`. A small Flutter background-service app doing the same request is the cleanest long-term fix.

## 5. How decisions are made

* Inside or outside is computed on the server (distance for circles, point-in-polygon for polygons).
* A flip needs **2 consecutive readings** and an accuracy better than 150 m, so GPS jitter at the boundary does not spam the log.
* A card's first fix sets its baseline: starting inside logs a Login; starting outside logs nothing.
* A card with no ping for 45 s shows as Offline. Editing the fence re-baselines cards silently, so it never creates fake logouts.
